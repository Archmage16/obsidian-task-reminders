# Obsidian Task Reminders

Задачи из Markdown с напоминаниями в отдельном Telegram-боте. Программа читает один файл задач, хранит очередь вне Obsidian и повторяет напоминания каждые два часа до выполнения или удаления задачи.

Рабочая схема развёртывания — Ubuntu и двусторонняя синхронизация `Задачи.md` через Syncthing в частной сети. Сервер отправляет напоминания самостоятельно; Obsidian нужен для удобного редактирования задач.

```markdown
- [ ] Подготовить отчёт 🔔 2026-10-18 18:00
- [ ] Проверить резервную копию 🔔 завтра 09:00
- [ ] Уточнить требования
```

Время — `Asia/Qyzylorda`, UTC+05. У строки без `🔔 даты времени` нет напоминания. `[x]` и удаление строки прекращают дальнейшие отправки; изменение срока переносит расписание. Изменение текста сохраняет задачу и обновляет содержание следующих напоминаний.

## Как устроено

- `reminders.py` разбирает Markdown, сопоставляет задачи с постоянными ID и обслуживает очередь SQLite.
- `markdown_store.py` сохраняет исходные байты перед добавлением ID и защищает запись Windows от конкурирующих сохранений.
- `bot_controls.py` обслуживает разрешённые владельцу кнопки отдельного бота.
- `bot_service.py` объединяет очередь и кнопки в одном процессе с общей блокировкой.
- `secrets_store.py` хранит токен вне исходного кода: Windows использует DPAPI текущего пользователя, Linux — Fernet с отдельным ключом.

Меню отдельного бота:

- **➕ Добавить задачу** (`/add`) — название и срок в коротком диалоге; задача записывается в серверный Markdown.
- **📝 Задачи** (`/tasks`) — активные, выполненные или все задачи; длинный список разбит на страницы.
- **📅 Дедлайны** (`/deadlines`) — сроки незавершённых задач, включая просроченные; задачи без срока показаны отдельно. Отображается срок задачи, а не время следующего двухчасового повтора.
- **✅ Проверить связь** — немедленный ответ бота.
- **⏱ Тест через 1 минуту** — отдельное отложенное сообщение; оно не создаёт задачу в Obsidian.
- **📋 Статус** — состояние очереди и процесса.

В напоминании есть **✅ Выполнено**, а под списком — **✅ номер задачи**, в том числе для задач без срока. Действие владельца отмечает соответствующую строку в Obsidian. Старый номер версии задачи не применяется к изменённому расписанию. На странице показывается до шести задач; кнопки и команды доступны владельцу в личном чате, страницы перечитывают актуальные серверные данные. Бот оценок работает самостоятельно.

Кнопки обрабатываются перед очередным напоминанием; между отправками бот снова проверяет команды. Дополнительной двухсекундной паузы после Telegram polling нет. При сетевых ошибках включается задержка повторных запросов, а одна попытка отправки ограничена таймаутом в пять секунд. Фактическое время ответа зависит от сети и Telegram.

## Создать задачу или изменить срок из Telegram

Нажми **➕ Добавить задачу** или отправь `/add Подготовить отчёт`. Если название не указано, бот попросит его следующим сообщением. Название — одна строка до 2000 символов; служебные комментарии, блоки кода и `🔔` в нём не используются.

Затем выбери **Через 2 часа**, **Завтра 09:00**, **Без срока** либо напиши дату: `2026-10-20 18:00`, `сегодня 18:00`, `завтра 09:00`. Время — UTC+05 (`Asia/Qyzylorda`); новый срок должен быть в будущем. Выбор даты или «Без срока» сразу сохраняет задачу, отдельного подтверждения перед записью нет. «Без срока» создаёт обычную задачу без напоминания.

Чтобы изменить срок существующей задачи, открой `/tasks` или `/deadlines` и нажми **🕒 номер задачи**. Выбери новый срок тем же способом; **Без срока** удаляет срок и прекращает напоминания. Если задачу успели удалить, выполнить или изменить её срок, старое действие отклоняется — открой свежий список.

**Отмена** или `/cancel` закрывает текущий диалог. Незавершённый черновик до отправки на сохранение истекает через час. Когда файл занят, бот сохраняет запрос и повторяет запись автоматически с тем же ID задачи, в том числе после перезапуска; ожидающий запрос не истекает через час. Отмена ожидающего запроса останавливает дальнейшие попытки, но не удаляет уже записанную задачу.

Сообщение «Сохранено на сервере» означает запись в серверную копию `Задачи.md`. В Obsidian изменение появится после Syncthing. Если подтверждение Telegram потерялось, бот повторяет подтверждение отдельно от записи; перед новым `/add` проверь `/tasks`. Пока сервер выключен, новый диалог и сохранение недоступны; после включения сначала требуется установить обновлённый код.

Задачи добавляются вне блоков кода. Если файл заканчивается незакрытым блоком, сначала закрой его: бот не добавляет задачу внутрь примера. Черновики и ожидающие запросы хранят названия задач в `controls.sqlite3` в частной папке данных. Эта база не включается в Git и безопасные статусы; она не заменяет зашифрованное хранение токена.

## Локальный запуск Windows

Нужен Python 3.11+ с Tkinter. Скопируй `config.example.json` в `config.json` и задай существующую папку Obsidian, имя файла задач и отдельную папку данных. Пути в примере предназначены для Ubuntu; в Windows используй свои абсолютные пути, например `C:/ObsidianVault` и `C:/ObsidianTasksData`.

Подключи отдельного бота через скрытое поле локального окна:

```powershell
py -3 setup_bot.py
```

После START у бота проверь доставку в окне. Токен вводится только локально: его не нужно помещать в `config.json`, заметки, историю команд или репозиторий.

Запуск объединённого процесса:

```powershell
py -3 bot_service.py --config config.json --watch
```

Для проверки очереди без отправки:

```powershell
py -3 reminders.py --config config.json --status
```

Работать должен один объединённый процесс. Перед переносом на сервер нужно остановить локальный экземпляр с тем же ботом.

## Сроки и повторы

`repeat_seconds: 7200` задаёт двухчасовой интервал после успешной отправки. `0` включает однократные напоминания. Перезапуск сохраняет очередь и время следующего повтора. После длительного перерыва программа отправляет одно догоняющее напоминание, без пачки за каждый пропущенный интервал.

«Сегодня» и «завтра» фиксируются при первом чтении задачи, а не сдвигаются ежедневно. Старую задачу, впервые обнаруженную значительно позже срока, нужно перенести на будущее; небольшой запас около срока учитывает задержку проверки файла.

После сетевой ошибки выполняется повторная попытка. Если Telegram принял сообщение, но ответ потерялся, возможна повторная доставка: API не предоставляет гарантии exactly-once для этой операции.

## Запись и восстановление

Перед изменением Markdown сохраняется точная исходная копия в `markdown-backups` внутри частной папки данных. На Windows удерживается файловый handle, запрещающий конкурирующую запись, удаление и замену до завершения операции. Занятый файл пропускается до следующей попытки.

После аварии старые резервные копии автоматически не возвращаются поверх новых правок. Для ручного восстановления сначала сравни текущий файл с копией. На Linux используется advisory lock и проверка замены файла синхронизатором; приложение без поддержки этой блокировки всё ещё может создать гонку при прямой перезаписи файла. Одновременное редактирование одной строки на двух устройствах может вызвать конфликт Syncthing: после него нужно сравнить версии.

## Ubuntu

Схема Ubuntu с Syncthing уже использовалась для развёртывания; установка и проверка описаны в [UBUNTU.md](UBUNTU.md). Windows DPAPI-файл нельзя расшифровать на Ubuntu. Linux backend хранит `token.enc` и соседний `.secret.key` в частной папке текущего пользователя; используется `cryptography>=41`. Новое создание задач и изменение срока подготовлены в исходном коде: после включения сервера нужно установить обновление и отдельно проверить запись, доставку и обратную синхронизацию.

Наличие исходного кода в GitHub не подтверждает работающий сервер. Для готовности требуется проверить, что сервер постоянно видит актуальный файл задач, получает изменения и запускается после перезагрузки.

### Когда компьютер выключен

Для уже синхронизированных задач сервер продолжает отправлять напоминания, даже если компьютер выключен, Obsidian закрыт или RDP отключён. Новые задачи и изменения на выключенном или отключённом компьютере сервер увидит после следующей синхронизации. Выполнение кнопкой Telegram изменяет серверную копию; отметка вернётся в Obsidian после подключения компьютера.

Без связи сервера с Telegram доставка задерживается; без работающего сервера сообщения не отправляются. После восстановления процесс повторяет попытки по сохранённой очереди. Выход из RDP не останавливает правильно установленную пользовательскую службу с включённым `linger`; перезагрузка требует включённого автозапуска обеих служб.

## Что хранится в Git

В репозитории находятся код, документация и конфигурация-пример. Рабочая конфигурация, токены, ключи, очередь SQLite, Telegram offsets, черновики и запросы сохранения, журналы, резервные копии и само хранилище Obsidian остаются вне Git. Перед первым коммитом используется явный список разрешённых файлов; `.gitignore` — дополнительная защита.

## Проверки

Автономные тесты используют временные файлы и поддельный Telegram transport. Они не читают рабочий токен и не отправляют сообщения:

```shell
python -m unittest discover -s tests -v
```

Проверки файлового доступа Windows запускаются только на Windows; остальные тесты используют доступный платформе backend. Успешные автономные тесты подтверждают локальную логику, а реальную доставку и синхронизацию проверяют отдельно после настройки.
